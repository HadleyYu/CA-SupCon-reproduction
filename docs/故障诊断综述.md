### B. 用一句话把故障诊断讲透

故障诊断不是“给一段信号分个类”这么窄。更准确地说，它是：

```text
把工业系统的运行数据转化成设备健康状态判断，并把这个判断进一步服务于报警、定位、解释、维护和安全控制。
```

如果只做分类，它像医生根据体检报告判断“你是什么病”。  
如果做预测性维护，它还要判断“这个病什么时候会恶化，什么时候治疗最合适”。  
如果做 PHM，它最终要服务整套健康管理流程：

```text
采集 -> 监测 -> 检测 -> 诊断 -> 预测 -> 决策 -> 维护 -> 反馈
```

IBM 对预测性维护的解释强调三件事：运行数据、实时状态监测、预测资产何时可能失效；它还把 IoT 传感器、AI/ML、CMMS、工单和维护调度连成一个业务闭环。AWS 的说明也把预测性维护拆成传感器采集、分析、行动三个动作：先持续捕获数据，再用 ML/AI 找偏离和失效模式，最后生成维护计划和告警。Azure 的开源方案则展示了一个云端预测性维护模板，包括数据生成、特征工程、模型训练、评估、部署和可视化 dashboard。

这说明一个现实问题：

```text
学术论文常常停在 TestAcc。
工业现场真正关心的是：能不能减少停机、减少误报、提前安排维护、让工程师相信它。
```

### C. 从“机器看病”到“工业闭环”

你可以把故障诊断想成一套工业医疗系统。

| 医疗系统 | 工业系统 |
|---|---|
| 病人 | 设备、生产线、化工过程、电机、轴承 |
| 体征 | 振动、温度、压力、电流、声学、图像 |
| 检查单 | 传感器时间序列、多变量过程数据 |
| 医生经验 | 机理知识、专家规则、维修记录 |
| 机器学习模型 | 自动诊断模型 |
| 诊断结论 | 正常、已知故障、未知故障、风险等级 |
| 治疗方案 | 维护计划、停机检修、备件调度、控制策略调整 |

一篇好的故障诊断论文，不应该只回答：

```text
我的模型准确率是多少？
```

还应该回答：

```text
我的模型解决了什么工业困难？
这个困难在真实现场为什么重要？
模型出错时错在哪些类别？
指标是否能反映少数类和严重故障？
换工况、换设备、遇到未知类、遇到噪声时还能不能用？
```

### D. 当前领域的核心矛盾

从公开综述和 benchmark 论文来看，故障诊断现在已经不是简单“CNN 比 SVM 高几个点”的阶段。真正难的矛盾大致有 10 个。

| 矛盾 | 现实原因 | 学术问题 |
|---|---|---|
| 样本少 | 严重故障不常发生，故障实验成本高 | few-shot、semi-supervised、data augmentation |
| 类别不平衡 | 正常样本多，故障样本少 | imbalanced learning、class-aware sampling、focal/prototype loss |
| 工况变化 | 转速、负载、环境、原料变化 | domain adaptation、domain generalization |
| 设备差异 | 不同机器结构、安装、传感器位置不同 | cross-machine transfer |
| 标签脏 | 维修记录不精确，故障开始时间不清楚 | label noise、weak supervision |
| 未知故障 | 测试时出现训练集中没有的故障 | open-set、OOD detection |
| 噪声和缺失 | 现场传感器干扰、断线、漂移 | robust learning、missing data imputation |
| 可解释性弱 | 工程师不信黑箱模型 | XAI、physics-guided learning |
| 实时部署难 | 边缘设备算力有限，延迟要求高 | compression、quantization、edge AI |
| 评估不公平 | 数据泄漏、切分不严、只报 Acc | leakage-free split、mean±std、per-class、MCC |

这 10 个矛盾，就是你以后找创新点的地图。

### E. 当前项目 CA-SupCon 在这张地图里的位置

你现在复现的 CA-SupCon 主要落在：

```text
类别不平衡 + 监督对比学习 + class-aware sampling
```

它不是解决所有故障诊断问题，而是解决一个很具体的问题：

```text
正常类样本多，故障类样本少。
普通 CE 分类器容易偏向多数类。
SupCon 希望把同类故障特征拉近、不同故障特征推远。
class-aware sampler 希望每个 batch 里少数类也有足够存在感。
```

当前复现结果说明：

```text
CWRU:
四个不平衡比例全部超过论文，说明这条复现链路是可靠的。

TE:
0.20 和 0.02 超过论文，0.10 和 0.05 略低于论文。
class 9、15、3 是最值得继续分析的弱类别。
```

因此，后续不要把创新重点放在“让 CWRU 再涨一点”。更合理的方向是：

```text
围绕 TE 弱类别，研究为什么某些故障类在整体 Acc 不低时仍然几乎识别不出来。
```

### G. 数据集：不是越多越好，而是要知道每个数据集在考什么

| 数据集 | 对象 | 主要考察 | 常见风险 |
|---|---|---|---|
| CWRU | 轴承振动 | 旋转机械故障分类 | 容易过高，切分不严会数据泄漏 |
| Paderborn PU | 轴承 | 更真实的人工/自然损伤 | 条件更多，实验设计要清楚 |
| XJTU-SY | 轴承退化 | RUL、退化趋势 | 不是简单分类即可解决 |
| NASA C-MAPSS | 航空发动机 | RUL 预测 | 目标是寿命回归，不是故障分类 |
| TE / TEP | 化工过程 | 多变量过程监控、异常检测、故障分类 | 故障动态阶段和窗口抽样影响很大 |
| PHM Challenge 数据 | 设备健康管理 | 综合诊断、预测、竞赛 benchmark | 指标和任务定义各不相同 |

官方 CWRU 页面列出了 48 kHz drive-end bearing fault data，并区分 fault diameter、motor load、inner race、ball、outer race 位置等条件。NASA PCoE Repository 明确说明其数据集用于 prognostic algorithms，许多数据是从正常状态走向失效状态的时间序列。TE 数据在过程监控里常被当成经典 benchmark，近期深度异常检测论文也强调它长期作为化工过程异常检测/诊断测试平台。

这告诉你：

```text
CWRU 适合入门和验证不平衡分类。
TE 更适合研究多变量耦合和过程动态。
NASA C-MAPSS 更适合 RUL。
不能把所有数据集都当成“分类准确率比赛”。
```

### H. 指标：为什么综述里必须强调评价口径

故障诊断最容易写虚的地方，就是只报 accuracy。

如果测试集平衡，Acc 可以看整体。  
如果类别不平衡，Acc 可能掩盖少数类崩溃。  
如果存在未知故障，Acc 甚至可能不适用。  
如果是 RUL，Acc 完全不是核心指标。

任务和指标应对应：

| 任务 | 应看指标 | 为什么 |
|---|---|---|
| 平衡分类 | Acc、F1、confusion matrix | 看整体分类是否正确 |
| 不平衡分类 | macro-F1、MCC、per-class accuracy | 防止多数类掩盖少数类 |
| 开放集 | AUROC、OSCR、unknown detection rate | 看能否拒识未知故障 |
| 异常检测 | AUROC、AUPR、FPR@TPR | 看异常和正常是否可分 |
| RUL | RMSE、MAE、NASA score | 看剩余寿命误差 |
| 跨域 | source/target 分开报告，mean±std | 看泛化和稳定性 |
| 工业部署 | 延迟、模型大小、误报率、漏报率 | 看能否实际上线 |

当前 CA-SupCon 项目正确地报告：

```text
Acc
macro-F1
MCC
per-class accuracy
10 seed mean ± std
```

这是严谨复现的基础。

### I. 最值得写成综述重点的 8 条趋势

#### 趋势 1：从“高精度分类”转向“可信诊断”

早期论文常常在 CWRU 上接近 100%。但 benchmark 研究已经提醒：不同划分、输入格式、归一化、增强、超参都可能影响结果，甚至让比较不公平。近年的不确定性研究进一步强调，工业系统需要知道模型什么时候不确定，尤其面对未知故障和噪声。

可写成综述观点：

```text
未来诊断模型不应只输出类别，还应输出置信度、不确定性和拒识能力。
```

#### 趋势 2：从单数据集刷分转向跨域泛化

真实工业现场不会永远保持同一转速、负载、传感器位置和设备状态。

所以迁移学习、域适应、域泛化会越来越重要：

```text
source domain: 有标签历史设备
target domain: 新设备、新工况、少标签或无标签
目标: 不重新大量标注，也能诊断可靠
```

#### 趋势 3：从黑箱深度网络转向物理知识融合

纯数据驱动方法容易学到伪相关。工业系统有机理、拓扑、变量关系、故障传播路径。把物理、语义、因果和图结构引入模型，是提高可信性的方向。

典型切入：

```text
故障机理约束
变量拓扑图
知识图谱
因果解耦
物理一致性 loss
```

#### 趋势 4：从单模态转向多模态

真实设备不只有一个传感器。振动、电流、温度、声学、图像、工况参数、维修记录都可能有用。

多模态诊断像会诊：

```text
振动像听诊
温度像体温
电流像心电
图像像 CT
维修记录像病历
```

难点不只是拼接特征，而是：

```text
不同模态采样频率不同
噪声水平不同
缺失情况不同
故障敏感性不同
```

#### 趋势 5：从离线论文实验转向在线持续学习

工业系统上线后会漂移：

```text
设备磨损
传感器老化
环境变化
工艺变化
维护后状态改变
```

因此持续学习、概念漂移检测、在线更新很重要。一个模型如果只在静态数据集上好，在真实系统中可能很快失效。

#### 趋势 6：从云端大模型转向边缘部署

预测性维护常常需要靠近设备实时判断。AWS 提到预测性维护系统可能涉及大量实时流数据和 IoT 来源，IBM 也强调 edge computing、digital twin 等趋势。

边缘部署要看：

```text
模型大小
推理延迟
功耗
传输成本
本地缓存
断网时是否可用
```

#### 趋势 7：从诊断到维护决策

分类只是说“它是什么故障”。维护决策要问：

```text
要不要停机？
什么时候停？
换哪个零件？
备件够不够？
误报成本和漏报成本哪个更高？
```

强化学习更适合接在诊断后面：

```text
状态 = 诊断概率 + 健康状态 + 生产计划 + 维护资源
动作 = 继续运行 / 降载 / 检修 / 更换部件
奖励 = 安全、成本、停机时间、产量综合权衡
```

#### 趋势 8：从小模型走向基础模型，但要谨慎

UniFault 这类研究说明，故障诊断也开始探索 foundation model。它试图把多来源轴承数据统一起来，做更通用的表征学习。

但故障诊断基础模型面临比图像/文本更难的问题：

```text
数据规模小
采样频率不统一
传感器通道数不统一
设备结构差异大
标签体系不统一
公开数据和真实现场差距大
```

因此，基础模型是趋势，但不是短期内所有问题的简单答案。

### J. 当前最适合你的选题切入口

结合当前 CA-SupCon 复现结果，最现实的选题不应该是“大而全的基础模型”，也不应该是“随便换 Transformer”。更合适的是：

```text
面向不平衡工业过程故障诊断的弱类别特征增强方法
```

为什么？

```text
1. 你已经有 CA-SupCon baseline。
2. CWRU 已经全部超过论文，说明平台可信。
3. TE 仍有弱类别，尤其 class 9、15、3。
4. 这个问题和不平衡、过程动态、对比学习、少数类边界都有关。
5. 可以从小改动开始，风险可控。
```

可以进一步细化成 5 个论文题目方向：

| 方向 | 题目雏形 | 核心问题 |
|---|---|---|
| prototype | 基于类原型约束的弱类别监督对比故障诊断 | 少数类中心不稳定 |
| hard negative | 面向易混淆故障的 hard-negative CA-SupCon | 类间边界太近 |
| adaptive temperature | 类别自适应温度监督对比学习 | 不同类分离难度不同 |
| stage-aware sampling | 面向 TE 过程动态阶段的窗口采样策略 | 故障演化阶段覆盖不足 |
| uncertainty | 不确定性感知的不平衡故障诊断 | 弱类别需要知道“我不确定” |

```text
   - RL maintenance decision

8. 结合当前项目的创新切入
   - CA-SupCon baseline
   - TE weak classes
   - proposed directions
```

## 先用几个比喻把这个方向讲活

如果你刚进团队，不要一开始就把故障诊断想成公式、网络结构和论文表格。先把它想成三个更熟悉的场景。

### 比喻一：机器看病

一台轴承、电机、齿轮箱或化工过程系统，就像一个病人。

| 医学诊断 | 工业故障诊断 |
|---|---|
| 病人说不舒服 | 设备振动、电流、温度、压力异常 |
| 心电图、血常规、CT | 振动信号、过程变量、电流信号、声学信号 |
| 医生判断感冒、肺炎、心梗 | 模型判断正常、内圈故障、外圈故障、阀门故障 |
| 罕见病病例很少 | 严重故障样本很少 |
| 新病毒没见过 | 未知故障 open-set |
| 不同医院设备不同 | 不同工况、不同设备 domain shift |
| 病情会发展 | 设备退化、概念漂移、RUL |

所以，故障诊断不是“给一串数字分类”这么简单，而是：

```text
把机器运行数据当成体检报告，训练一个懂工业机理的医生，判断机器到底出了什么问题。
```

这个比喻能帮你理解几个核心难点：

- 正常样本很多，就像普通感冒病例很多。
- 严重故障很少，就像罕见病病例很少。
- 新工况像换了医院、换了检查设备，过去训练的医生可能不适应。
- 未知故障像新病种，医生不能硬把它归到已知病里。
- 工业现场噪声像检查仪器受干扰，体检报告里有很多杂音。

### 比喻二：听声音修车

老维修师傅常常能“听声辨故障”。发动机一响，他可能就知道是皮带松了、轴承坏了、齿轮磨了。

深度学习故障诊断本质上是在做类似的事：

```text
人耳听声音 -> 大脑提取经验特征 -> 判断故障
传感器采信号 -> 神经网络提取特征 -> 输出故障类别
```

区别是，模型不是直接“懂声音”，它看到的是数字序列：

```text
0.023, 0.031, -0.012, -0.066, ...
```

一段振动信号里可能有冲击、周期、噪声、转速变化。CNN 像一个自动扫描局部波形的放大镜，LSTM 像一个记住前后变化的听诊器，TCN 像一个多尺度时间滤镜，Attention 像告诉模型“这几段声音更关键”的聚光灯。

### 比喻三：侦探破案

工业故障诊断也像侦探破案。

```text
案发现场：设备运行异常
线索：传感器信号、报警记录、工况参数、维修记录
嫌疑人：各种已知故障类别
侦探：诊断模型
证据链：特征、原型、注意力、图结构、物理知识
```

普通分类模型像一个经验不足的侦探：看到多数类线索多，就容易把案件都判成常见故障。对比学习和度量学习像训练侦探建立“案件相似度地图”：同一种故障的线索应聚在一起，不同故障的线索应分开。域适应像侦探从成都调到上海，犯罪手法变了、监控设备变了，但仍要用旧经验快速适应新现场。开放集诊断像遇到从未见过的新型案件，侦探不能硬塞到旧案库里，而要说“这是未知类型，需要人工确认”。

### 一张脑内总图

你可以先把整个方向记成下面这张图：

```text
真实工业系统
  |
  | 传感器采集
  v
原始信号：振动 / 电流 / 温度 / 压力 / 多变量过程数据
  |
  | 切窗口、标准化、增强、划分数据集
  v

  |

特征空间：正常类一团，故障1一团，故障2一团...
```

## 0. 先给结论：这个方向到底研究什么

故障诊断研究的是：

```text
给定设备或工业过程运行数据，判断系统是否异常、是什么故障、故障发生在哪里、为什么会这样，以及后续如何维护。
```

在凡时财教授团队近期论文中，这个方向更具体地表现为：

```text
面向旋转机械、工业过程、多源传感系统的智能故障诊断，重点解决少样本、不平衡、跨工况、跨域迁移、未知故障、噪声干扰、多模态融合和非平稳漂移问题。
```

如果你是新博士，第一阶段不要把它理解成“换一个神经网络刷准确率”。更准确的理解是：

```text
真实工业系统很复杂，故障数据少、标签贵、工况变、噪声强、未知类多、部署后还会漂移。
故障诊断论文的价值在于，把这些真实约束抽象成可研究的问题，并设计可靠、可验证、可迁移的诊断方法。
```

凡时财教授团队近期研究主线可以粗略概括为六类：

| 主线 | 典型问题 | 代表关键词 |
|---|---|---|
| 时序特征学习 | 怎样从振动/过程时间序列中提取有效特征 | LSTM、TCN、多尺度、注意力 |
| 类别不平衡 | 故障类样本远少于正常类怎么办 | metric learning、SupCon、class-aware |
| 迁移学习与域适应 | 工况变了、设备变了、目标域无标签怎么办 | transfer learning、domain adaptation、source-free |
| 域泛化与开放集 | 目标域未知、未知故障出现怎么办 | domain generalization、open-set、unknown fault |
| 多模态与知识融合 | 多传感器、多源知识如何结合 | cross-modal fusion、knowledge graph、GNN |
| 可靠工业部署 | 噪声、漂移、持续学习、实时性怎么办 | noise robust、concept drift、continual adaptation |

## 1. 基础概念：故障诊断、故障检测、PHM 的关系

### 1.1 故障检测、诊断、定位不是一回事

故障相关任务常见名称很多，刚入门时最容易混淆。

| 名称 | 英文 | 回答的问题 | 常见输出 |
|---|---|---|---|
| 故障检测 | fault detection | 有没有异常 | 正常/异常 |
| 故障诊断 | fault diagnosis | 是哪一种故障 | 故障类别 |
| 故障隔离 | fault isolation | 故障来自哪个部件或变量 | 部件、传感器、过程单元 |
| 故障定位 | fault localization | 故障发生在系统哪个位置 | 位置、节点、变量 |
| 故障预测 | fault prediction | 未来是否会故障 | 风险概率、剩余时间 |
| 剩余寿命预测 | RUL prediction | 还能运行多久 | remaining useful life |
| 容错控制 | fault tolerant control | 故障后如何保持系统可控 | 控制策略 |

你现在复现的 CA-SupCon 属于：

```text
已知故障类别下的监督式多分类故障诊断。
```

但凡时财教授团队论文并不只做这个，还扩展到迁移、开放集、漂移、跨模态、故障定位等更复杂问题。

### 1.2 PHM 是更大的框架

PHM 是 Prognostics and Health Management，通常翻译为故障预测与健康管理。它包含：

```text
传感器采集
-> 状态监测
-> 异常检测
-> 故障诊断
-> 故障定位
-> 健康评估
-> 剩余寿命预测
-> 维护决策
```

所以故障诊断是 PHM 中的一环。学术论文里常常只做分类准确率，但工业落地时还要关心：

- 误报会不会太多。
- 漏报严重故障会不会造成安全事故。
- 新设备、新工况上线后模型还能不能用。
- 传感器损坏、噪声、缺失值会不会让模型崩溃。
- 工程师能不能理解模型为什么报警。
- 模型部署后是否能持续更新。

### 1.3 为什么它属于控制科学与工程

传统控制领域长期研究 fault detection and diagnosis，典型路线包括：

- 基于状态空间模型的残差生成。
- 基于观测器的故障检测。
- 基于卡尔曼滤波的状态估计。
- 基于参数估计的异常识别。
- 基于鲁棒控制和容错控制的安全运行。

深度学习故障诊断看起来像机器学习，但它的对象仍然是工业系统、控制系统、装备系统和生产过程。因此在控制学科里，关键不是单纯说“我用了 CNN/Transformer”，而是要说清楚：

```text
这个方法解决了工业系统中的什么诊断约束？
它如何提高系统运行安全、可维护性、可靠性或可迁移性？
```

## 2. 工业故障诊断的数据到底长什么样

这一节要解决一个最基础但非常重要的问题：论文里说的 `sample`、`window`、`feature`、`domain` 到底对应现实里的什么东西。

### 2.0 从一条振动信号到一行论文表格

假设你现在有一台轴承试验台，传感器贴在轴承座上，采集到一条振动信号。

原始信号长这样：

```text
时间:  0ms   1ms   2ms   3ms   4ms   ...
振动: 0.01  0.03 -0.02  0.10 -0.04  ...
```

如果轴承内圈有裂纹，每转一圈，滚动体经过裂纹位置时可能产生一次冲击。于是信号里会出现某种周期性的尖峰。但现场很乱，尖峰可能被负载变化、背景振动、传感器噪声淹没。

一篇故障诊断论文通常把这条长信号变成实验结果，大致经历下面 11 步。

#### 第 1 步：采集原始数据

```text
设备运行 -> 传感器采样 -> 得到长时间序列
```

对应现实：

- 轴承振动传感器采加速度。
- 电机采电流、电压、转速。
- 化工过程采温度、压力、流量、液位等变量。

新手常见误解：

```text
以为数据集里的每一行就是设备一次完整运行。
```

实际上很多数据集是一条或几条长信号切出来的很多窗口。

#### 第 2 步：切窗口

模型不能直接吃一条特别长的信号，所以要切成固定长度窗口。

```text
长信号: [------------------------------------------------------]

窗口1:  [------]
窗口2:     [------]
窗口3:        [------]
窗口4:           [------]
```

窗口长度决定模型看到的时间范围。窗口太短，可能看不到完整故障周期；窗口太长，样本数减少，计算量变大。

在 CWRU 中，常见窗口可以是：

```text
每个样本 = 400 个连续采样点
shape = [1, 400]
```

在 TE 工业过程里，常见窗口可以是：

```text
每个样本 = 52 个变量 x 200 个时间点
shape = [52, 200]
```

#### 第 3 步：贴标签

每个窗口要有标签：

```text
0 = normal
1 = inner race fault 0.007 inch
2 = inner race fault 0.014 inch
...
```

标签从哪里来？

- 实验台数据：故障类别是人为设置好的。
- 工业现场数据：标签可能来自报警记录、维修记录、专家标注。

现场标签通常更脏，因为维修记录可能不规范，故障发生时间也不一定精确。

#### 第 4 步：划分训练、验证、测试

```text
train: 用来训练模型
val:   用来选最优 epoch 和调参
test:  最后只评估一次，报告论文结果
```

一定要避免数据泄漏。比如同一条连续信号切出的高度重叠窗口，如果前一半进 train，后一半进 test，模型可能只是记住了相邻波形，不是真正学会诊断。

#### 第 5 步：构造真实难题

很多论文不是简单随机划分，而是故意构造更接近工业现场的问题。

不平衡：

```text
normal: 1800
fault_1: 36
fault_2: 36
...
```

跨工况：

```text
source: 负载 1 hp
target: 负载 3 hp
```

少样本：

```text
每个新故障只给 5 个标注样本
```

开放集：

```text
训练只见过 fault_1 到 fault_5
测试出现 fault_6，但模型必须识别它是 unknown
```

#### 第 6 步：数据预处理

常见处理：

- 标准化，让不同量纲可比较。
- 去趋势，去掉慢变漂移。
- 滤波，降低噪声。
- 时频变换，把一维信号变成频谱或时频图。
- 数据增强，制造同一故障的不同视图。

CA-SupCon 里的增强可以理解成：

```text
同一台机器的同一种故障，在真实现场不会每次波形一模一样。
所以对信号做轻微加噪、缩放、平移，让模型学到更稳定的故障特征。
```

#### 第 7 步：模型提特征

模型输入一个窗口，输出一个特征向量。

```text
原始窗口 [1, 400]
  -> 1D CNN / ResNet / TCN
  -> feature [100]
```

你可以把 feature 想象成医生写在病历里的“综合判断摘要”：

```text
原始检查报告很长
医生看完后总结成几个关键信息
模型也是把长信号压缩成一个特征向量
```

#### 第 8 步：分类或度量

普通分类：

```text
feature -> classifier -> 每个类别的概率
```

度量学习/对比学习：

```text
feature -> 特征空间
同类靠近，不同类远离
```

开放集识别：

```text
如果样本离所有已知类都远，或者置信度异常，就判为 unknown
```

#### 第 9 步：训练

训练就是不断让模型犯错、改错。

```text
预测 -> 和真实标签比较 -> 算 loss -> 反向传播 -> 更新参数
```

CA-SupCon 的训练更像双任务：

```text
任务一：分类器要分对类别
任务二：特征空间要排得漂亮
```

这就是：

```text
total loss = CE loss + lambda * SupCon loss
```

#### 第 10 步：评估

训练结束后，在 test set 上评估。

不要只看：

```text
TestAcc = 95%
```

还要看：

```text
少数故障类是不是也识别好了？
未知故障有没有被拒识？
跨工况目标域表现如何？
多次随机 seed 是否稳定？
```

#### 第 11 步：形成论文表格

最终论文表格可能长这样：

```text
Method      5:1        10:1       20:1       50:1
CNN         91.2±1.1   88.4±1.8   82.0±2.7   70.5±4.2
SupCon      95.6±0.7   93.0±1.0   90.1±1.5   84.2±2.4
CA-SupCon   97.1±0.4   95.8±0.8   93.3±1.1   89.0±1.8
```

你要能从这张表反推整个实验：

```text
用了什么数据？
怎么构造不平衡？
每个 ratio 是什么含义？
跑了几个 seed？
指标是 Acc、F1 还是 MCC？
为什么 50:1 最难？
CA-SupCon 为什么更稳？
```

这才是真正读懂论文。

### 2.1 常见对象

故障诊断对象大致分为几类。

| 对象 | 数据形式 | 常见故障 | 代表任务 |
|---|---|---|---|
| 轴承 | 振动、一维时间序列 | 内圈、外圈、滚动体故障 | 旋转机械故障分类 |
| 齿轮箱 | 振动、转速、扭矩 | 齿裂纹、断齿、磨损 | 机械传动诊断 |
| 电机 | 电流、电压、振动、温度 | 轴承故障、转子断条、传感器故障 | 电机驱动系统诊断 |
| 工业过程 | 多变量时序 | 过程扰动、阀门、传感器、执行器故障 | 化工过程监控 |
| 水电机组 | 多测点、多源信号 | 振动、摆度、温度、压力异常 | 故障定位与诊断 |
| 芯片/电子系统 | 电流、温度、监测电路信号 | 互连、封装、局部模块异常 | 健康监测与自诊断 |

凡时财教授团队近期论文常见对象包括：

- rotating machinery fault diagnosis。
- bearing fault diagnosis。
- industrial process fault diagnosis。
- hydroelectric units fault localization。
- multi-source industrial fault diagnosis。
- in-situ health monitoring for 3D heterogeneous integrated systems。

### 2.2 输入信号形态

最常见输入是时间序列。

单传感器振动信号：

```text
x = [x1, x2, ..., xT]
shape: [1, T]
```

多变量工业过程信号：

```text
X = [变量数 x 时间长度]
shape: [C, T]
```

多模态信号：

```text
振动 + 电流 + 声音 + 温度 + 转速 + 工艺变量
```

图结构或知识结构：

```text
变量/部件/传感器作为节点
物理连接、统计相关、因果关系作为边
```

### 2.3 为什么要切窗口

原始工业信号通常很长，模型不能直接吃整条序列，所以会切成窗口：

```text
原始长序列
-> 按固定长度 T 切片
-> 每个窗口作为一个样本
-> 给每个窗口贴标签
```

比如 CWRU 轴承数据常用窗口长度 400，TE 过程数据常用窗口长度 200。窗口长度影响：

- 能否覆盖足够的故障周期。
- 样本数量多少。
- 模型计算量。
- 标签是否稳定。

### 2.4 常见公开数据集

| 数据集 | 类型 | 特点 | 适合研究 |
|---|---|---|---|
| CWRU | 轴承振动 | 经典入门数据，类别清晰 | 基础分类、不平衡、迁移 |
| Paderborn | 轴承 | 工况更丰富，真实损伤和人工损伤 | 跨工况泛化 |
| MFPT | 轴承 | 数据规模较小 | 入门验证 |
| XJTU-SY | 轴承全寿命 | 退化过程 | RUL、健康状态评估 |
| IMS | 轴承全寿命 | 长时间运行 | RUL、异常检测 |
| Tennessee Eastman | 工业过程 | 多变量化工过程仿真 | 过程监控、故障检测/诊断 |
| DAMADICS | 阀门/执行器 | 过程控制故障 | 过程故障诊断 |
| NASA C-MAPSS | 涡扇发动机 | 多工况退化 | RUL 预测 |

新博士必须注意：公开数据集很方便，但不能把公开数据集准确率当成全部研究价值。真正的问题通常来自：

```text
跨工况、跨设备、少标签、未知故障、噪声、漂移、可解释性、工业部署。
```

## 3. 评价指标：不能只看 Accuracy

### 3.1 分类任务常见指标

| 指标 | 含义 | 适合场景 | 风险 |
|---|---|---|---|
| Accuracy | 总体预测正确比例 | 类别均衡、初步比较 | 不平衡时可能虚高 |
| Precision | 预测为某类时有多少是真的 | 误报成本高 | 单独看不够 |
| Recall | 某类真实样本有多少被找出来 | 漏报成本高 | 可能牺牲 precision |
| F1 | precision 和 recall 折中 | 不平衡分类 | 要说明 macro/micro/weighted |
| Macro-F1 | 每类 F1 平均 | 重视少数类 | 小类波动大 |
| MCC | 相关系数式综合指标 | 不平衡、多分类 | 解释门槛稍高 |
| AUC | 阈值无关排序能力 | 二分类/多标签 | 多分类需定义口径 |

不平衡故障诊断中，Accuracy 很容易误导。例如正常类占 90%，模型全部预测正常，也能有 90% Acc，但故障诊断能力为零。

所以团队的 CA-SupCon 这类论文通常需要看：

```text
Acc + F1 + MCC + per-class accuracy + 多 seed 均值和标准差
```

### 3.2 开放集和未知故障还要看什么

开放集故障诊断不仅要识别已知类，还要发现未知类。常见指标包括：

- 已知类分类准确率。
- 未知类检测准确率。
- OSCR 曲线。
- AUROC。
- FPR@TPR95。
- H-score。

如果论文说解决 open-set fault diagnosis，却只报闭集 accuracy，是不够的。

### 3.3 迁移学习和域适应要看什么

跨域诊断中要区分：

- 源域准确率不重要，目标域准确率才关键。
- 是否使用目标域标签必须说清楚。
- 是否多源域、多目标域、多工况平均。
- 是否存在类别集合不一致。
- 是否做多次随机重复。

论文表格中常见设置：

```text
A -> B
B -> C
C -> A
平均准确率 mean ± std
```

## 4. 方法演化：从传统诊断到深度智能诊断

### 4.1 阶段一：机理模型和专家规则

早期故障诊断强调机理、控制模型和专家经验。

典型方法：

- 阈值报警。
- 频谱分析。
- 包络谱分析。
- 状态估计。
- 残差生成。
- 观测器方法。
- 专家系统。

优点：

- 可解释性强。
- 对小样本友好。
- 工程师容易理解。

缺点：

- 依赖专家经验。
- 难处理复杂非线性。
- 泛化能力有限。
- 多变量耦合系统建模困难。

### 4.2 阶段二：信号处理 + 传统机器学习

典型流程：

```text
原始信号
-> 手工特征提取
-> 特征选择/降维
-> 分类器
```

常见手工特征：

- 时域：均值、方差、RMS、峰值、峭度、偏度、峰峰值。
- 频域：FFT、功率谱、特征频率、边频带。
- 时频域：STFT、小波变换、EMD、VMD、HHT。

常见模型：

- PCA、KPCA、DPCA。
- PLS、ICA。
- SVM、KNN、Random Forest、XGBoost。
- GMM、HMM。

这类方法仍然值得学，因为它们提供了故障诊断的物理直觉。深度学习不是替代所有传统知识，而是把特征学习自动化。

### 4.3 阶段三：深度学习特征提取

深度学习把流程变成：

```text
原始信号窗口
-> 神经网络自动提特征
-> 分类器输出故障类别
```

常见结构：

| 模型 | 适合数据 | 优点 | 缺点 |
|---|---|---|---|
| 1D-CNN | 振动、过程时间序列 | 局部模式提取强，训练快 | 长时依赖有限 |
| 2D-CNN | 时频图、谱图 | 可借鉴图像模型 | 依赖变换质量 |
| ResNet | 深层网络 | 缓解梯度消失 | 参数更多 |
| LSTM/GRU | 序列数据 | 建模时间依赖 | 训练慢，长序列困难 |
| TCN | 时间序列 | 并行、感受野可控 | 超参设计重要 |
| Attention/Transformer | 长依赖、多变量 | 建模全局关系 | 数据少时易过拟合 |
| GNN | 传感器/部件图 | 建模结构关系 | 图构建困难 |

凡时财教授团队早期智能诊断论文中，LSTM、TCN、多尺度 TCN、注意力增强 TCN 是重要起点。

### 4.4 阶段四：真实工业约束驱动的方法

现在故障诊断论文越来越少满足于“闭集、同工况、有大量标签”。更重要的问题包括：

| 真实约束 | 学术问题 | 常见方法 |
|---|---|---|
| 故障样本少 | few-shot / limited labels | metric learning、meta-learning、prototype、semi-supervised |
| 类别不平衡 | imbalanced fault diagnosis | re-sampling、re-weighting、contrastive learning |
| 工况变化 | transfer / domain adaptation | MMD、adversarial、pseudo label、source-free |
| 目标域未知 | domain generalization | invariant feature、ensemble、causal disentanglement |
| 未知故障出现 | open-set / open-world | threshold、unknown detection、dual-stage recognition |
| 噪声强 | noise robust diagnosis | denoising、attention、uncertainty |
| 多传感器 | multimodal fusion | cross-modal attention、graph fusion |
| 长期部署 | continual / drift adaptation | continual learning、concept drift detection |

凡时财教授团队近年的论文基本都在这些真实约束上展开。

## 5. 关键研究问题一：类别不平衡故障诊断

### 5.1 为什么不平衡是故障诊断的核心矛盾

工业系统里正常数据多，故障数据少，这是常态。

原因包括：

- 设备大部分时间正常运行。
- 严重故障很少发生。
- 故障实验代价高。
- 真实故障标签需要专家确认。
- 某些故障发生后设备会停机，不可能持续采集大量样本。

典型训练集可能是：

```text
normal: 1800
fault_1: 36
fault_2: 36
fault_3: 36
...
```

这会导致模型偏向多数类，少数故障边界不清晰。

### 5.2 常见解决方法

| 方法 | 思路 | 优点 | 风险 |
|---|---|---|---|
| 过采样 | 复制或生成少数类 | 简单 | 过拟合 |
| 欠采样 | 减少多数类 | 平衡训练 | 浪费数据 |
| 类别权重 | 少数类 loss 权重大 | 易实现 | 权重难调 |
| Focal loss | 关注难样本 | 对难分类样本有效 | 超参敏感 |
| 数据生成 | GAN/VAE/diffusion 生成故障 | 扩充数据 | 生成质量难保证 |
| 度量学习 | 学特征距离 | 改善特征空间 | batch 构造重要 |
| 对比学习 | 同类拉近、异类推远 | 表征更清晰 | 依赖增强和采样 |

### 5.3 团队代表论文：Quadruplet Deep Metric Learning

论文：`A Quadruplet Deep Metric Learning model for imbalanced time-series fault diagnosis`，Knowledge-Based Systems，2022。

作者：Xingtai Gui, Jiyang Zhang, Jianxiong Tang, Hongbing Xu, Jianxiao Zou, Shicai Fan。

这篇论文要解决的问题：

```text
不平衡时间序列故障诊断中，少数类样本少，普通分类 loss 学到的特征空间不够可分。
```

核心思想：

```text
与其只让分类器最后分对，不如直接约束特征空间。
让同类样本更近，不同类样本更远，并特别关注不平衡类别下的类间距离关系。
```

你可以把它理解成 CA-SupCon 之前的一条逻辑：

```text
普通 CE 分类
-> metric learning 改善特征空间
-> supervised contrastive learning 进一步利用 batch 内多正负样本关系
```

入门阅读重点：

- 它如何构造 quadruplet。
- 它和 triplet loss 的区别。
- 它如何针对少数类样本设计距离约束。
- 实验中不平衡比例怎么设置。
- 指标是否看了 per-class 或 macro 指标。

### 5.4 团队代表论文：CA-SupCon

论文：`A class-aware supervised contrastive learning framework for imbalanced fault diagnosis`，Knowledge-Based Systems，2022。

作者：Jiyang Zhang, Jianxiao Zou, Zhiheng Su, Jianxiong Tang, Yuhao Kang, Hongbing Xu, Zhiliang Liu, Shicai Fan。

这篇是你当前项目复现的论文。

它解决的问题：

```text
不平衡故障诊断中，少数故障类样本少，普通 CE 容易偏向多数类；同时 SupCon 需要 batch 内有足够正负样本关系，普通随机采样可能让少数类参与不足。
```

核心组件：

| 组件 | 作用 |
|---|---|
| 时序数据增强 | 给同一样本构造两个不同视图 |
| 共享 backbone | 提取原始样本和增强样本特征 |
| SupCon loss | 同类特征拉近，异类特征推远 |
| CE loss | 保持最终分类能力 |
| class-aware sampler | 让 batch 内类别更均衡，少数类有更多对比机会 |

训练逻辑：

```text
view1 -> backbone -> feature1 -> normalize
view2 -> backbone -> feature2 -> normalize
原始样本 -> backbone -> classifier -> CE loss
[feature1, feature2] + label -> SupCon loss
total loss = CE loss + lambda * SupCon loss
```

这篇论文为什么重要：

- 它把监督对比学习引入不平衡故障诊断。
- 它不是只改 loss，还配合 class-aware sampling。
- 它把“特征空间结构”作为不平衡诊断的核心。
- 它自然连接后续的对比学习、度量学习、原型学习、少样本诊断。

新博士读这篇时要问：

```text
1. 为什么 CE 不够？
2. 为什么 SupCon 对少数类有帮助？
3. 为什么 batch 构造会影响 SupCon？
4. 数据增强是否符合故障信号物理意义？
5. class-aware sampler 是否会改变原始数据分布？
6. 如果目标域变了，CA-SupCon 还能不能直接用？
```

## 6. 关键研究问题二：时序特征学习

### 6.1 为什么故障诊断需要时序模型

故障信号不是普通表格数据。它包含：

- 局部冲击。
- 周期性模式。
- 频率成分。
- 长短期动态。
- 多变量耦合。
- 工况变化下的非平稳性。

因此模型要能抓住时间结构。

### 6.2 LSTM 路线

论文：`A novel fault diagnosis method based on stacked LSTM`，IFAC-PapersOnLine，2020。

作者：Q Zhang, Jiyang Zhang, Jianxiao Zou, Shicai Fan。

要解决的问题：

```text
工业过程故障数据具有时间依赖，单个时刻或浅层模型难以捕捉动态变化。
```

核心思想：

```text
用 stacked LSTM 从多变量时间序列中提取时间依赖特征，再进行故障检测和诊断。
```

入门价值：

- 帮你理解为什么工业过程故障诊断不是简单静态分类。
- 帮你熟悉 detection 和 diagnosis 两个任务。
- 是从传统过程监控走向深度序列模型的过渡。

### 6.3 TCN 路线

论文：`MS-TCN: A Multiscale Temporal Convolutional Network for Fault Diagnosis in Industrial Processes`，American Control Conference，2021。

作者：Jiyang Zhang, Yuxuan Wang, Jianxiong Tang, Jianxiao Zou, Shicai Fan。

要解决的问题：

```text
工业过程信号有不同时间尺度的动态模式，单一卷积尺度可能无法充分捕捉故障特征。
```

核心思想：

```text
用多尺度 temporal convolution 提取不同时间范围的动态特征。
```

TCN 相比 LSTM 的优势：

- 卷积可并行，训练效率高。
- 感受野可以通过 dilation 和 kernel 设计控制。
- 对长序列建模比普通 CNN 更强。

### 6.4 注意力增强 TCN

论文：`AME-TCN: Attention mechanism enhanced temporal convolutional network for fault diagnosis in industrial processes`，Global Reliability and Prognostics and Health Management Conference，2021。

作者：Jiyang Zhang, Yang Chang, Jianxiao Zou, Shicai Fan。

要解决的问题：

```text
不同变量、不同时间片段对故障诊断贡献不同，普通 TCN 可能不能突出关键部分。
```

核心思想：

```text
在 TCN 基础上加入 attention mechanism，让模型强调更重要的时间或特征区域。
```

你要理解：

- attention 不是魔法，本质是加权。
- 在故障诊断中，attention 的价值是突出关键变量、关键时间段、关键特征尺度。
- 如果论文声称可解释，需要看 attention 是否真的对应物理意义。

### 6.5 深度并行时间序列关系网络

论文：`A Novel Deep Parallel Time-Series Relation Network for Fault Diagnosis`，IEEE Transactions on Instrumentation and Measurement，2023。

作者：Chun Yang, Jiyang Zhang, Yang Chang, Jianxiao Zou, Zhiliang Liu, Shicai Fan。

要解决的问题：

```text
故障时间序列中不仅有单变量时间模式，还有不同时间片段、不同通道或不同特征之间的关系。
```

核心思想：

```text
用并行结构建模时间序列关系，提高诊断性能和一定程度的可解释性。
```

这条线对新博士的启发：

```text
不要只问“用什么 backbone”，还要问“故障信息以什么关系存在”。
是时间关系、变量关系、频率关系、工况关系，还是样本间关系？
```

## 7. 关键研究问题三：迁移学习与域适应

### 7.1 为什么迁移是工业诊断核心问题

在公开数据集上，训练集和测试集常常来自相同分布。但真实工业里，训练环境和部署环境通常不同。

常见 domain shift：

- 转速不同。
- 负载不同。
- 设备型号不同。
- 传感器位置不同。
- 噪声水平不同。
- 维护后系统状态变化。
- 原材料、工艺配方、环境温度变化。

形式化表示：

```text
源域 source domain: 有大量标签
目标域 target domain: 标签少或没有标签
目标：利用源域知识提升目标域诊断性能
```

### 7.2 迁移学习常见类别

| 类型 | 标签情况 | 代表问题 |
|---|---|---|
| supervised transfer | 目标域有少量标签 | 小样本迁移 |
| unsupervised domain adaptation | 目标域无标签 | 常见跨工况诊断 |
| semi-supervised domain adaptation | 目标域少量标签 + 大量无标签 | 更贴近工业 |
| source-free domain adaptation | 源数据不可访问，只能用源模型 | 隐私/存储限制 |
| universal domain adaptation | 源域和目标域类别集合不完全一致 | 未知类别/类别不匹配 |
| domain generalization | 训练时看不到目标域 | 更难、更贴近未知部署 |
| continual domain adaptation | 目标域持续变化 | 长期部署 |

### 7.3 常见技术路线

| 路线 | 思想 | 典型方法 |
|---|---|---|
| 分布对齐 | 让源域和目标域特征分布接近 | MMD、LMMD、CORAL |
| 对抗适应 | 用域判别器学域不变特征 | DANN、CDAN |
| 决策边界适应 | 让目标样本远离错误边界 | discrepancy、entropy minimization |
| 伪标签 | 给目标域无标签样本生成标签 | self-training、label propagation |
| 原型适应 | 维护每类中心或锚点 | prototype、anchor |
| 图传播 | 利用样本关系传播标签 | graph diffusion、GNN |
| 源无关适应 | 只用源模型和目标数据 | source-free adaptation |

### 7.4 团队代表论文：Deep Joint Transfer Network

论文：`Deep Joint Transfer Network for Intelligent Fault Diagnosis under Different Working Conditions`，American Control Conference，2022。

作者：Zhiheng Su, Jiyang Zhang, Jianxiong Tang, Yang Chang, Jianxiao Zou, Shicai Fan。

要解决的问题：

```text
不同工况下源域和目标域数据分布不同，直接用源域训练模型会性能下降。
```

核心思想：

```text
通过联合迁移网络对齐跨工况特征分布，提升目标工况诊断性能。
```

读这篇要关注：

- 它对齐的是边缘分布还是条件分布。
- 是否使用 LMMD 这类类别条件对齐。
- 目标域是否有标签。
- 实验任务是否是多个工况之间互相迁移。

### 7.5 团队代表论文：Inter-domain Decision Discrepancy Minimization

论文：`A novel deep transfer learning method with inter-domain decision discrepancy minimization for intelligent fault diagnosis`，Knowledge-Based Systems，2023。

作者：Zhiheng Su, Jiyang Zhang, Jianxiong Tang, Yuxuan Wang, Hongbing Xu, Jianxiao Zou, Shicai Fan。

要解决的问题：

```text
只做特征分布对齐可能不够，目标域样本仍可能落在错误决策边界附近。
```

核心思想：

```text
最小化跨域决策差异，使源域和目标域在分类决策层面更一致。
```

这篇论文体现的趋势：

```text
早期域适应关注 feature alignment，后来越来越关注 decision boundary、classifier discrepancy 和 class-level structure。
```

新博士要思考：

- 特征对齐是否可能把不同类别错误对齐。
- 决策边界如何影响目标域分类。
- 伪标签错误会不会被放大。

### 7.6 团队代表论文：Few Source Data + Sensitivity-aware Decision Boundary

论文：`Deep semi-supervised transfer learning method on few source data with sensitivity-aware decision boundary adaptation for intelligent fault diagnosis`，Expert Systems with Applications，2024。

作者：Zhiheng Su, Jiyang Zhang, Hongbing Xu, Jianxiao Zou, Shicai Fan。

要解决的问题：

```text
不仅目标域标签少，源域标注数据也少。传统迁移学习默认源域大量有标签，这在工业中并不总成立。
```

核心思想：

```text
在少源数据条件下，结合半监督迁移和对决策边界敏感的适应机制，提升目标域诊断。
```

这篇论文对选题很重要，因为它指出：

```text
工业诊断不能总假设源域很完美。
源域少、目标域少、标签噪声、类别缺失，都可能是下一步问题。
```

### 7.7 团队代表论文：Source-free Domain Adaptation

论文：`Semi-supervised source-free domain adaptation method via diffusive label propagation for rotating machinery fault diagnosis`，Reliability Engineering & System Safety，2024。

作者：Zhiheng Su, Penglong Lian, Penghui Shang, Jiyang Zhang, Hongbing Xu, Jianxiao Zou, Shicai Fan。

要解决的问题：

```text
工业中源域数据可能因为隐私、存储或商业限制无法共享，只能拿到源模型和目标域数据。
```

核心思想：

```text
在 source-free 条件下，通过扩散式标签传播利用目标域样本结构，改善伪标签和适应效果。
```

为什么重要：

- source-free 更贴近工业合作场景。
- label propagation 强调样本间图结构。
- semi-supervised 表示可能利用少量目标标签。

读这篇时要关注：

- 源模型如何初始化。
- 目标域图如何构建。
- 标签扩散如何避免错误传播。
- 半监督标签比例如何影响结果。

### 7.8 团队代表论文：Universal Domain Adaptation

论文：`Two-head classifier guided domain adversarial learning for universal domain adaptation in intelligent fault diagnosis`，Reliability Engineering & System Safety，2025。

作者：Jiyang Zhang, Xiangxiang Wang, Zhiheng Su, Penglong Lian, Hongbing Xu, Jianxiao Zou, Shicai Fan。

要解决的问题：

```text
源域和目标域类别集合可能不完全相同。目标域可能有源域没有的未知故障，源域也可能有目标域不存在的类别。
```

普通 UDA 的隐含假设是：

```text
源域类别集合 = 目标域类别集合
```

但 universal domain adaptation 放宽为：

```text
源域和目标域类别集合部分重叠，存在私有类和共享类。
```

核心思想：

```text
用双头分类器引导域对抗学习，在类别集合不一致时区分共享类和私有/未知类，避免错误对齐。
```

这篇论文很适合连接 open-set fault diagnosis，因为二者都关心未知类别。

## 8. 关键研究问题四：域泛化、开放集与持续适应

### 8.1 域泛化比域适应更难

域适应通常训练时能看到目标域无标签数据。域泛化更苛刻：

```text
训练时只有若干源域，目标域完全不可见。
```

这更贴近以下场景：

- 设备还没部署到新现场。
- 目标工况未来才出现。
- 不能提前采集目标域数据。

域泛化的核心是学到 invariant feature，即不同源域之间稳定、可迁移的故障表征。

### 8.2 团队代表论文：Weighted Ensemble Domain Generalization

论文：`A weighted ensemble domain generalization method via multi-level invariant feature learning for rotating machinery fault diagnosis`，2024。

作者：Zhiheng Su, Jiyang Zhang, Penglong Lian, Jianxiao Zou, Shicai Fan。

要解决的问题：

```text
未知目标工况下，没有目标域数据可用，普通域适应不适用。
```

核心思想：

```text
通过多层级不变特征学习和加权集成，提高模型对未知目标域的泛化能力。
```

你要理解：

- domain adaptation 是“看见目标域后适应”。
- domain generalization 是“没见过目标域也要泛化”。
- ensemble 可以降低单模型对某个源域偏差的依赖。

### 8.3 团队代表论文：Physics-semantics Guided Causal Disentanglement

论文：`Physics-semantics guided causal disentanglement for domain generalization in rotating machinery fault diagnosis`，Advanced Engineering Informatics，2026。

作者：Penglong Lian, Junlin Song, Penghui Shang, Jianxiao Zou, Shicai Fan。

要解决的问题：

```text
域泛化中，模型容易学习到与工况相关但与故障本质无关的伪相关特征。
```

核心思想：

```text
利用物理语义指导因果解耦，把更接近故障本质的因果特征与域相关干扰因素分开。
```

这代表一个非常重要的趋势：

```text
从纯数据驱动，走向物理知识、语义约束、因果表示与深度模型结合。
```

新博士如果想做高质量选题，可以重点关注：

- 什么是故障因果特征。
- 物理语义如何注入模型。
- 如何证明解耦不是可视化幻觉。
- 域泛化是否真的在未知工况上有效。

### 8.4 开放集故障诊断

闭集假设：

```text
训练类别 = 测试类别
```

开放集假设：

```text
测试时可能出现训练中没见过的未知故障。
```

这对工业系统很关键，因为真实现场不可能提前收集所有故障模式。

团队相关论文：

`Dual-stage recognition framework for open-set fault diagnosis in rotating machinery considering varying inter-class similarity`，Control Engineering Practice，2026。

作者：Penglong Lian, Penghui Shang, Jianxiao Zou, Shicai Fan。

要解决的问题：

```text
未知故障和某些已知故障可能很相似，不同类别之间相似度不同，简单统一阈值容易误判。
```

核心思想：

```text
用双阶段识别框架处理已知类分类和未知类拒识，并考虑类间相似度差异。
```

读开放集论文时要问：

- 未知类是如何构造的。
- 训练时是否见过未知类。
- 阈值如何设定。
- 已知类准确率和未知检测率如何权衡。
- 是否比较了 open-set 专用指标。

### 8.5 持续域适应与概念漂移

长期部署后，目标域不会静止不变。可能发生：

- 工况缓慢变化。
- 设备老化。
- 传感器漂移。
- 维护后系统状态改变。
- 新故障模式出现。

团队相关论文：

`Continual unsupervised domain adaptation with structure-preserving probabilistic anchors for rotating machinery fault diagnosis`，Advanced Engineering Informatics，2026。

作者：Penglong Lian, Jianxiao Zou, Jianxiong Tang, Shicai Fan。

要解决的问题：

```text
目标域持续变化时，模型需要不断适应，同时不能灾难性遗忘已有知识。
```

核心思想：

```text
用结构保持的概率锚点维护类别/域结构，在连续无监督域适应中保持诊断稳定性。
```

团队相关会议论文：

`Multi-Scale Feature-Probability Consistency for Domain Concept Drift Detection in Non-Stationary Industrial Fault Diagnosis`，IECON，2025。

作者：Penglong Lian, Junlin Song, Jiyang Zhang, Jianxiao Zou, Shicai Fan。

要解决的问题：

```text
非平稳工业诊断中，需要检测域概念漂移，并判断模型何时需要适应或更新。
```

这条线未来价值很高，因为它从“离线论文实验”走向“在线长期运行”。

## 9. 关键研究问题五：多模态、图结构与知识融合

### 9.1 为什么单一传感器不够

真实工业系统通常有多源数据：

- 振动。
- 电流。
- 电压。
- 声音。
- 温度。
- 压力。
- 流量。
- 转速。
- 工艺变量。
- 维修记录。
- 拓扑结构。

单模态方法容易遗漏互补信息。例如轴承故障可能同时反映在振动和电流中；工业过程故障可能需要多个变量之间的耦合关系才能识别。

### 9.2 多模态融合方式

| 融合方式 | 做法 | 优点 | 风险 |
|---|---|---|---|
| 数据级融合 | 原始信号拼接 | 简单 | 采样率和尺度不一致 |
| 特征级融合 | 各模态提特征后融合 | 灵活 | 融合模块设计复杂 |
| 决策级融合 | 各模型输出再投票/加权 | 鲁棒 | 丢失细粒度交互 |
| 注意力融合 | 学习不同模态权重 | 自适应 | 可解释性需验证 |
| 图融合 | 把变量/传感器作为图节点 | 能建模结构 | 图构建困难 |

### 9.3 团队代表论文：Dual-Stream Cross-Modal Feature Fusion

论文：`Dual-Stream Cross-Modal Feature Fusion Based on Multi-Scale Attention for Industrial Fault Diagnosis`，American Control Conference，2024。

作者：Penglong Lian, Penghui Shang, Jiyang Zhang, Zhiheng Su, Jianxiao Zou, Shicai Fan。

要解决的问题：

```text
单一模态特征不足，多模态信息之间存在互补关系，但简单拼接不能充分利用跨模态交互。
```

核心思想：

```text
用双流结构分别提取不同模态特征，再通过多尺度注意力进行跨模态融合。
```

读这篇要关注：

- 两个 stream 分别处理什么模态。
- cross-modal fusion 发生在哪一层。
- 多尺度 attention 如何定义。
- 融合后是否对噪声或不平衡更鲁棒。

### 9.4 团队相关方向：Knowledge Graph + GNN

Google Scholar 公开条目显示团队有论文：

`Knowledge Graph-Driven Graph Neural Network with Multi-Source Knowledge for Industrial Fault Diagnosis`，Global Reliability and Prognostics and Health Management Conference，2025。

作者：Penglong Lian, Jiyang Zhang, Junlin Song, Jianxiao Zou, Shicai Fan。

要解决的问题：

```text
工业故障诊断不仅有传感器数据，还有设备结构、变量关系、专家知识、故障机理等多源知识。
```

核心思想：

```text
构建知识图谱，并用图神经网络融合多源知识，提高诊断性能和可解释性。
```

这条线非常适合控制学科，因为它可以把：

```text
工业机理 + 专家知识 + 数据驱动模型
```

结合起来。

## 10. 关键研究问题六：噪声鲁棒与复杂环境

### 10.1 为什么噪声是工业现场常态

公开数据集往往比较干净，但现场数据会有：

- 电磁干扰。
- 机械背景噪声。
- 传感器老化。
- 安装松动。
- 数据缺失。
- 异常尖峰。
- 多设备耦合干扰。

如果模型只在干净数据上效果好，落地价值有限。

### 10.2 团队代表论文：DTCNA-Net

论文：`DTCNA-Net: Dual temporal convolutional neural network with noise estimation and attention mechanism for intelligent fault diagnosis under the complex noise environment`，2024。

作者：Jiyang Zhang, Jianxiao Zou, Zhiheng Su, Penglong Lian, Shicai Fan。

要解决的问题：

```text
复杂噪声环境下，有效故障特征被噪声淹没，普通深度模型性能下降。
```

核心思想：

```text
用双 temporal convolutional network 结构结合噪声估计和注意力机制，提高复杂噪声下的诊断鲁棒性。
```

读这篇时要关注：

- 噪声是人工添加还是现场真实噪声。
- 噪声类型有哪些。
- SNR 设置是否合理。
- 是否比较了不同噪声强度下性能曲线。
- 注意力是否真的关注有效故障特征。

## 11. 关键研究问题七：少样本故障诊断

### 11.1 少样本和不平衡有什么区别

不平衡关注类别样本数量差异：

```text
正常类很多，故障类很少。
```

少样本关注某些类别本身样本极少：

```text
每个新故障可能只有 1、5、10 个样本。
```

二者常同时出现，但研究问题不同。

### 11.2 常见少样本方法

| 方法 | 思想 |
|---|---|
| metric learning | 学一个距离空间，让同类近、异类远 |
| prototypical network | 每类用原型表示，新样本看离哪个原型近 |
| matching network | 用支持集和查询集相似度分类 |
| relation network | 学习样本对之间关系 |
| meta-learning | 学会快速适应新任务 |
| graph neural network | 利用样本图传播标签 |
| data generation | 生成额外少样本故障数据 |

### 11.3 团队相关论文：Multi-scale Graph Convolution Filtering

论文：`Few-shot fault diagnosis based on multi-scale graph convolution filtering for industry`，arXiv，2024。

作者：Mengjie Gan, Penglong Lian, Zhiheng Su, Jiyang Zhang, Jialong Huang, Benhao Wang, Jianxiao Zou, Shicai Fan。

要解决的问题：

```text
工业少样本故障诊断中，可用标注样本很少，普通深度模型容易过拟合。
```

核心思想：

```text
构建样本关系图，通过多尺度图卷积滤波提取更稳健的少样本类别结构。
```

读这篇要关注：

- few-shot 任务如何构造。
- N-way K-shot 设置是什么。
- 图节点和边如何定义。
- 多尺度图滤波如何提升泛化。

## 12.7 团队论文逐篇生动导读卡片

这一节专门给新博士用。你不需要第一次就看懂所有公式，但应该能看懂每篇论文在“工业现场”里到底想解决什么麻烦。

### 卡片 1：Stacked LSTM，像让模型学会“看病程”

论文：`A novel fault diagnosis method based on stacked LSTM`，2020。

现实画面：

```text
医生不能只看病人某一秒的体温，而要看体温、心率、血压随时间怎么变化。
工业过程也一样，某个变量单独某一刻不一定异常，但一段时间的动态变化可能暴露故障。
```

这篇论文的直觉：

```text
把工业过程数据当成一段病程记录，让 LSTM 记住前后时间依赖，再判断是否故障、是哪种故障。
```

它解决的核心矛盾：

- 工业过程变量不是独立静态点。
- 故障会在时间上逐步表现出来。
- 传统静态模型可能忽略动态过程。

你读这篇时要抓住：

- 输入序列长度是多少。
- stacked LSTM 为什么比单层 LSTM 更强。
- detection 和 diagnosis 是否分开做。
- 它如何处理多变量过程数据。

一句话记忆：

```text
LSTM 让模型从“看一张检查单”升级为“看一段病程”。
```

### 卡片 2：MS-TCN，像用不同倍数放大镜看故障

论文：`MS-TCN: A Multiscale Temporal Convolutional Network for Fault Diagnosis in Industrial Processes`，2021。

现实画面：

```text
看机器故障，有些线索很短，比如一次冲击；有些线索很长，比如一段过程变量缓慢漂移。
只用一种尺度看，就像只拿一个倍数的放大镜。
```

这篇论文的直觉：

```text
用多尺度 TCN 同时看短期局部变化和较长期动态模式。
```

它解决的核心矛盾：

- 故障特征可能存在于不同时间尺度。
- 普通 CNN 感受野有限。
- RNN 训练慢，长序列不方便。

你读这篇时要抓住：

- 多尺度怎么实现，是不同 kernel、不同 dilation，还是不同分支。
- TCN 的感受野如何覆盖时间依赖。
- 多尺度特征最后如何融合。

一句话记忆：

```text
MS-TCN 是给模型配了几把不同焦距的时间放大镜。
```

### 卡片 3：AME-TCN，像给模型一个“重点标注笔”

论文：`AME-TCN: Attention mechanism enhanced temporal convolutional network for fault diagnosis in industrial processes`，2021。

现实画面：

```text
医生看报告时，不会平均看每一项，而会重点看异常指标。
模型看时间序列时，也不应该平均对待每个时间点和每个变量。
```

这篇论文的直觉：

```text
在 TCN 基础上加入 attention，让模型自动强调更关键的时间段或特征通道。
```

它解决的核心矛盾：

- 多变量过程数据里，不是所有变量都和当前故障相关。
- 不同时间片段的信息量不同。
- 普通卷积可能把关键特征和无关背景混在一起。

你读这篇时要抓住：

- attention 加在时间维、通道维，还是特征维。
- attention 是否能解释故障变量。
- 与 MS-TCN 相比提升来自哪里。

一句话记忆：

```text
AME-TCN 是让 TCN 学会“划重点”。
```

### 卡片 4：Quadruplet DML，像训练模型认清“谁和谁更像”

论文：`A Quadruplet Deep Metric Learning model for imbalanced time-series fault diagnosis`，2022。

现实画面：

```text
如果医生只背答案，可能遇到少见病就误判。
更好的训练是让医生比较病例：这个病例和哪个病例更像？和哪个病例明显不同？
```

这篇论文的直觉：

```text
不用只依赖分类器最后分对，而是直接训练特征空间中的距离关系。
```

它解决的核心矛盾：

- 不平衡数据中少数类样本少，分类边界不稳。
- CE loss 不一定让同类样本在特征空间紧密聚集。
- 少数类需要更明确的类内紧凑、类间分离约束。

你读这篇时要抓住：

- quadruplet 里的四个样本分别是谁。
- 它比 triplet 多约束了什么。
- 它如何照顾不平衡类别。

一句话记忆：

```text
Quadruplet DML 是教模型建立“病例相似度地图”。
```

### 卡片 5：CA-SupCon，像让每类故障都在地图上形成自己的村庄

论文：`A class-aware supervised contrastive learning framework for imbalanced fault diagnosis`，2022。

现实画面：

```text
如果把每个样本放到地图上，理想情况是：正常样本住一个村，内圈故障住一个村，外圈故障住一个村。
普通 CE 只要求最后门牌号分对，不一定要求村庄分布清楚。
SupCon 则要求同村的人靠近，不同村的人远离。
```

这篇论文的直觉：

```text
用监督对比学习整理特征空间，用 class-aware sampler 保证少数类也能充分参与对比。
```

它解决的核心矛盾：

- 不平衡下少数类容易被多数类淹没。
- 随机 batch 里少数类样本少，SupCon 正样本关系不足。
- 只靠 CE 不能保证少数类特征聚得好。

核心机制像这样：

```text
同一样本 -> 两个增强视图
同类样本 -> 互相拉近
不同类样本 -> 互相推远
class-aware sampler -> 每个 batch 更均衡
```

你读这篇时要抓住：

- 为什么需要两个增强视图。
- 为什么 class-aware sampler 是关键，不是小配件。
- CE 和 SupCon 分别优化什么。
- lambda、temperature、batch size 如何影响结果。

一句话记忆：

```text
CA-SupCon 是在不平衡数据里帮少数类故障“建村庄、立边界”。
```

### 卡片 6：Deep Joint Transfer Network，像把成都师傅调到上海修机器

```text
一个师傅在成都工厂修过很多机器，现在被派到上海工厂。机器类型类似，但负载、环境、传感器安装位置不一样。
```

这篇论文的直觉：

```text
源域有标签，目标域工况不同。通过对齐源域和目标域特征，让模型在新工况上也能诊断。
```

它解决的核心矛盾：

- 训练工况和测试工况分布不一致。
- 目标域标签少或没有。
- 直接用源域模型会性能下降。

你读这篇时要抓住：

- source domain 和 target domain 怎么定义。
- 它对齐了什么分布。
- 是否用 MMD/LMMD 类方法。
- 迁移任务如何构造。

一句话记忆：

```text
Deep Joint Transfer Network 是让老工况经验迁移到新工况。
```

### 卡片 7：Inter-domain Decision Discrepancy，像不仅口音要像，判案标准也要一致

```text
两个医生看病例，一个在源医院，一个在目标医院。即使他们提取的检查特征差不多，如果最后判断标准不一致，还是会误诊。
```

```text
域适应不能只看特征分布像不像，还要看分类决策边界是否对目标域友好。
```

它解决的核心矛盾：

- 只做 feature alignment 可能造成错误对齐。
- 目标样本可能靠近错误决策边界。
- 分类器层面的差异会影响最终诊断。

你读这篇时要抓住：

- decision discrepancy 如何定义。
- 它和 MMD/对抗域适应有什么不同。
- 是否用了多个分类器或决策差异约束。

一句话记忆：

```text
这篇把迁移学习从“特征像不像”推进到“判案标准是否一致”。
```

- 持续学习和概念漂移。
- 物理语义、因果解耦、多源知识融合。

## 14. 怎么读一篇故障诊断论文

不要从公式开始读。推荐固定模板。

### 14.1 第一遍：看问题

回答：

```text
这篇论文解决什么工业约束？
```

常见答案应该像这样：

- 类别不平衡。
- 目标域无标签。
- 源数据不可用。
- 目标域有未知故障。
- 噪声环境。
- 少样本。
- 多模态。
- 非平稳漂移。

如果你读完只知道“它用了某个网络”，说明还没读懂。

### 14.2 第二遍：看假设

重点看：

- 训练和测试是否同分布。
- 目标域是否有标签。
- 源域是否可访问。
- 类别集合是否一致。
- 是否知道未知类数量。
- 是否使用目标测试集信息调参。
- 是否多次随机重复。

很多论文差异不在模型，而在假设。

### 14.3 第三遍：看方法组件

拆成：

```text
输入是什么
backbone 是什么
loss 有哪些
采样策略是什么
是否有伪标签
是否有域对齐
是否有图结构
训练流程几阶段
推理时怎么判别
```

### 14.4 第四遍：看实验是否可信

检查：

- 数据集是否足够。
- 对比方法是否合理。
- 消融实验是否对应每个模块。
- 指标是否符合任务。
- 是否报告 mean ± std。
- 是否有参数敏感性分析。
- 是否有可视化但不过度依赖 t-SNE。
- 是否有工业解释。

### 14.5 第五遍：想自己的改进点

常见改进方向：

- 更真实的问题假设。
- 更稳健的伪标签。
- 更好的类别结构建模。
- 引入物理先验。
- 改善未知类检测。
- 处理持续漂移。
- 提升可解释性。
- 减少计算量，便于部署。

## 16. 新博士必须掌握的故障诊断专业知识

### 16.1 旋转机械基础

至少要知道：

- 轴承结构：内圈、外圈、滚动体、保持架。
- 典型故障：inner race、outer race、ball fault。
- 振动信号为什么能反映故障。
- 转速和负载为什么造成工况变化。
- 频谱和包络谱为什么常用。

### 16.2 工业过程基础

至少要知道：

- 多变量时间序列。
- 过程变量之间耦合。
- Tennessee Eastman process 为什么经典。
- 故障检测和故障诊断在过程监控中的区别。
- DPCA、PCA、PLS 等传统过程监控方法。

### 16.3 数据处理基础

必须掌握：

- 窗口切分。
- 标准化。
- 训练/验证/测试划分。
- 类别不平衡构造。
- 跨工况任务构造。
- 多 seed 重复实验。
- 数据泄漏检查。

数据泄漏非常重要。常见错误包括：

- 先对全数据标准化，再划分 train/test。
- 同一连续信号切出来的高度重叠窗口同时出现在 train 和 test。
- 用测试集调阈值或超参。
- 目标域标签被间接用于无监督适应。

## 20. 论文写作时最容易犯的错误

### 20.1 只说模型，不说问题

错误写法：

```text
本文提出一种新的 CNN-Transformer 网络。
```

更好的写法：

```text
针对跨工况不平衡故障诊断中少数类目标域伪标签不可靠的问题，本文提出...
```

### 20.2 只和弱 baseline 比

必须比较：

- 传统机器学习。
- 普通 CNN/LSTM/TCN。
- 同类最新方法。
- 任务专用方法。

例如做域适应，就不能只和 CNN 比，还要和 DANN、MMD、CDAN、source-free 方法比较。

### 20.3 实验设置不严谨

常见问题：

- 数据泄漏。
- 没有多 seed。
- 测试集调参。
- 不平衡任务只报 accuracy。
- 开放集任务只报闭集准确率。
- 迁移任务没有说明目标域标签是否使用。

### 20.4 可解释性停留在 t-SNE

t-SNE 可以辅助展示，但不能作为主要证据。更好的解释包括：

- 频域/时域关键区域分析。
- 变量重要性与工业机理对应。
- 类别原型或锚点解释。
- attention 与故障变量对应。
- 消融验证物理知识是否有效。

### 20.5 创新点只是模块堆叠

不好的创新：

```text
CNN + Transformer + attention + contrastive + GNN
```

好的创新：

```text
针对某个真实约束，设计一个必要且可解释的机制，并用实验说明它解决了该约束。
```

## 28. 最后建议

你作为团队新博士，最重要的不是马上提出复杂模型，而是尽快建立三个能力：

```text
1. 能把工业诊断问题讲清楚。
2. 能把团队论文脉络串起来。
3. 能把一个想法落到严谨实验上。
```

短期最推荐的切入路径：

```text
CA-SupCon 复现
-> 不平衡表征学习
-> 跨工况迁移学习
-> source-free / open-set / domain generalization 中选一个真实约束深入
```

只要你能把“问题假设、数据设置、方法机制、评价指标、工业意义”五件事讲清楚，就已经从普通调参者进入博士研究状态。
